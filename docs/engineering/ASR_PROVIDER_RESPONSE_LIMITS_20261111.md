# StepFun ASR：响应大小与读取任务释放（2026-11-11）

设备上传的 PCM 已有 60 秒大小边界，但上游响应是另一项独立资源：原 StepFun SSE 解析器
会持续累加没有分隔符的正文或增量文本，只有时间预算；HTTP 错误路径调用 `response.text()`
完整读取后才截取 200 字符。收到 SSE error 或解析失败时只释放 reader 锁，没有取消未完成
的响应体。上游不关闭时可保留网络/缓冲，错误正文也可掩盖原 HTTP 失败而拖至超时。

## 修正

- 成功 HTTP 的 SSE 原始输入累计最多 1 MiB，包含所有事件和 keepalive。先检查本次 chunk
  的 byteLength，再解码或拼接；不因已消费完整事件而重置总数。超过预算明确返回 asr_failed，
  不把部分转写标成完成，不启动后续聊天或工具，不重试提供商请求。
- HTTP 错误只为现有诊断消息保留最多 1024 个原始字节，显示仍限制为 200 字符。大 chunk
  只解码所需前缀，随后停止读取并取消剩余响应；空错误体保持原状态映射。
- 两条路径在退出时取消响应并释放锁。取消本身可能拒绝或永远不结束，不能等待它掩盖原错误
  或延长操作期限。调用方取消/超时仍取消实际 reader 并沿用既有取消/超时分类。

1 MiB 是本应用的响应资源政策，不是 StepFun 模型输出能力或服务端声明的限制。它独立于
音频上传字节数/采样率和原有绝对 ASR 时限；没有调整模型、API、热词、提示词、delta/done
语义或回退开关。[StepFun 官方示例](https://github.com/stepfun-ai/StepAudio-Skills/blob/main/skills/step-asr/scripts/transcribe.py)
用于核对既有请求/事件字段；本批没有调用真实提供商，官方文档站超时不作为协议变更依据。

## 验证及边界

新模拟流用例在旧源码下 10 项中 9 项因目标断言失败，恰好 1 MiB、跨 chunk UTF-8 和 CRLF
的正常响应通过。修正后的所有用例及真实流水线回归覆盖：单块/累计超限、错误事件后不关流、
HTTP 错误正文不关流、取消拒绝/不结束、调用方取消、绝对时限、部分转写后超限不得进入聊天。
具体结果、语义负对照、TypeScript 和提交 hook 记录见工作区 doc/asr-stream-bounds-20261111/。

这些是生产函数加可控 fetch/stream 的本地证据。原实机轮次 77d7ecc1156db6f0 很快收到 done
而无已解析文本，现有证据不证明本缺陷导致该轮失败；首轮空转写根因仍未确认。真实端点、网络、
