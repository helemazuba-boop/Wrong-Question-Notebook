# 普通语音请求：取消、时限及提供商身份错误（2026-11-11）

普通Agent转写和STD转写聊天没有将Request.signal传给提供商。StepFun有自己的超时，
DashScope每次提交/查询/下载重新开始完整超时，轮询等待也不能取消。主ASR失败后可能在
调用方已取消时再发起回退；ASR完成后还可能继续聊天、执行后续工具或保存对话。
此外，StepFun和DashScope的上游401/403原样成为设备接口状态，混淆提供商凭据与设备准入。

## 当前行为

- 普通两入口传递Request.signal。提供商输入的signal为可选内部参数，不由HTTP请求正文指定。
  ASR的主/备提供商、提交、轮询等待及结果下载共享一个单调时间预算。请求前、异步交接与
  回退前检查停止条件，网络等待和JSON读取受同一取消/期限控制。
- 暂存音频若在取消之后才完成，后续只清理暂存结果，不发起模型请求。已经取得的暂存对象在
  错误/超时时清理；不能将尚未返回的文件操作描述为已被物理中断。
- 聊天阶段的上下文读取、网络及各轮共享LLM时限；取消后不调度下一模型/工具或开始对话写入。
  已发起的工具/对话写入等待真实结果，不强制中断、撤销或重放，因此等待写回执可能超过时限。
  请求取消不会证明已开始写入没有生效；真实写回执、幂等ID和未知结果规则继续适用。
  调用方已断连时可能收不到回执，499/504不能当作未写入证明，应按已有幂等回执机制确认。
- 已进入ASR/聊天处理的普通请求主动取消返回应用状态499、code=cancelled；自身超时仍为504及既有错误码。
  服务端提供商的401/403映射为502，错误分类保持原样。真实设备准入401/403、429及其他
  请求校验仍走原路径；没有将鉴权失败改成成功，也没有让设备清除有效配对。
- 同一上游状态隔离适用于普通提供商、StepFun SSE、流式ASR JSON和流式聊天HTTP边界。

没有改变提供商、模型、默认时间预算、回退开关、工具写入策略或语音字段合同，也没有读取真实
key或调用模型。普通JSON助手读取使用已有voice-operation原语；云端API变更仍需部署后验收。
