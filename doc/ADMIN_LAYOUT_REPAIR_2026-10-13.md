# 管理后台布局与国际化修复

按用户描述的 1664 × 928 截图现象，在当前分支的旧生产构建中复现，再检查组件、样式、翻译和真实统计接口。本轮沿用现有配色、字体与卡片样式。

## 根因与修复

| 现象                         | 已定位根因                                                                                                               | 针对性修复                                                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 主体居中且过窄               | `(app)/layout.tsx` 的 `page-container` 使用 `max-w-6xl`，两侧 padding 使后台实际宽度只有 1104px；内部又有 `max-w-7xl`    | `AppMain` 按路由为后台使用全宽主容器，普通应用页面保留原有宽度；移除后台内层最大宽度，桌面侧栏调整为 240px，主列使用 `minmax(0,1fr)` |
| 快捷操作文字、图标和箭头挤压 | 外层两列面板、面板内两列卡片都按视口固定展开，而侧栏已吃掉一部分宽度；图标默认可收缩                                     | 面板按 28rem、快捷卡片按 15.5rem 的可用空间自动换列；文字区域 `min-w-0`，图标与箭头禁止收缩，文字自然换行                            |
| 页面和后台内部同时滚动       | 后台 `h-screen` 叠加顶部导航、外部 padding；内层 `main` 又设置 `overflow-auto`                                           | 只保留页面纵向滚动，后台使用减去导航高度的最小高度；窄屏侧栏改为模态抽屉，抽屉自身允许滚动且锁定背景页面                             |
| 统计卡片窄、数值与单位折行   | 视口 `lg` 下固定四/五列，数值与图标争用同一横排                                                                          | 统计网格按 14rem 最小可用宽度自动换列；图标和标题一行，数值单独一行、按语言格式化并保持数值与单位相邻                                |
| 中文环境仍显示英文后台文案   | Sidebar、QuickActions、RecentActivityFeed 的固定文案硬编码英文；Admin namespace 已正常加载                               | 接入现有 Admin / Reports 翻译键，补齐快捷操作描述、角色、未知用户；活动相对日期使用当前语言                                          |
| 存储下方仅出现“个文件”       | 两种语言的 `Admin.files` 都缺少插值，但 Dashboard 和用户详情已传入实际 `count`；API 映射为 `storageStats.fileCount` 正确 | 中文增加 `{count, number}`，英文按实际数量使用单复数；两个调用点自动受益，不硬编码数量                                               |
| 存储数量可能被低估           | 原聚合把 size=0 判为非文件、只取每层首个 1000 条对象并忽略列表错误                                                       | 依据对象 ID 区分文件与目录；分页、递归计数包含空文件；接口或 size 元数据缺失明确失败；更新后台缓存版本                               |
| 英文窄屏顶部导航溢出         | 八个导航链接从 768px 即横排展开，英文品牌名、链接和用户信息占用超出可用空间                                              | 在 1536px 起展开完整导航，以下使用已存在的菜单；品牌名及链接禁止异常折行，菜单使用独立的翻译标签                                     |

## 复现与证据

- 旧构建的浏览器几何断言在 1664px 失败：后台宽度实测 1104px，预期应大于 1616px。旧画面保存为 `artifacts/admin-layout/before-zh-CN-1664.png`；可见窄快捷卡片和折成两行的 `9.2 MB`。
- 修复后同一分辨率的后台占满约 1649px 可用宽度（浏览器纵向滚动条占用约 15px）。卡片、图标、箭头均不溢出，`9.2 MB` 保持一行。普通页面在同一文档导航后仍不超过原有 1152px 上限。
- 测试使用隔离 Supabase 的实际 Auth、Storage、PostgREST 和 Next 生产构建。真实上传约 9.2 MiB 的文件及一个空文件，API 返回实际字节数和 `fileCount=2`，界面分别显示 `2 个文件`、`2 files`。
- 浏览器用例检查中文、英文以及 1664、1536、1440、1280、1024、768、390px 的宽度，检查唯一 main、无页面横向溢出、无后台内部纵向滚动、统计卡片和快捷操作几何位置，以及后台抽屉和应用导航菜单的开关行为。
- Linux 浏览器的中文字体使用临时 Fontconfig 配置指向本机已有 Noto Sans SC，只影响测试进程；应用字体和系统配置未修改。浏览器通过临时 HTTPS 网关和可信测试证书访问，TLS 校验保持启用。

## 验证

- 新增 10 项单元回归：实际文件数量 0/1/42、英文单复数、中文后台静态文案、空文件、1001 个对象分页、用户前缀、列表失败和缺失 size。
- 全量 Vitest：152 个文件、1509 项通过，两个数据库集成启用，没有跳过。
- 类型检查、生产构建、客户端密钥检查通过；翻译检查两种语言 2491 个键一致。
- Chromium、移动 Chromium、Firefox、WebKit 原有 48 项流程回归全部通过。新增后台用例初次运行的菜单角色选择器不符实际链接语义；修正后另跑四个浏览器项目均通过，共验证 52 项用例。后台覆盖两种语言、七种宽度、真实统计及导航开关；原有回归覆盖普通页面、公式/图片持久化、学习恢复、导入、引导、提醒和举报权限。
- 提交前的完整 lint 和格式检查通过：lint 0 errors、164 warnings；diff 与禁止追踪路径检查通过。测试证书、密钥、环境文件和截图均未提交。

本轮未增加数据库迁移，未对生产数据或部署执行操作。统计仍沿用 `problem-uploads` 桶及每用户原有的 `user/<id>` 前缀；真实接口验证来自隔离测试环境。
